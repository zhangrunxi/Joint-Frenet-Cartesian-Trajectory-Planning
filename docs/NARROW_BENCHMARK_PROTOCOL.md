# 窄路实验协议（冻结于运行之前，2026-10-30）

本协议在运行 `scripts/run_random_benchmark.py --task gap|curb` 之前写定。
它针对论文引言中声明的适用场景：长轴距公交车在**窄路、大曲率**下，
近似几何的误差与保守性会吃掉可行空间（main.tex 第 142、213 行）。
宽路结果（`RANDOM_BENCHMARK_PROTOCOL.md`）保留为对照，不删除、不替换。

所有方法使用同一车辆：6.50 m × 2.30 m、轴距 4.32 m、后悬 1.00 m（`bus_vehicle()`），
障碍物为同尺寸公交车；同一评估器（`paper_comparison/evaluation.py`，精确矩形）。
道路裕量 0.2 m、障碍物裕量 0.2 m，与既有实验一致。

## 0. 对既有超越任务指标的更正

既有超越任务的 `success` 只表示“跑满 120 步且无碰撞/越界”，**不要求超过障碍物**。
一直跟在障碍物后面的运行也计为成功。本协议对“需要超越”的任务统一采用：

> **通过 = `success` 且 `passed_obstacle`**（后轴 s 超过障碍物 s + 6.5 m）

## 1. E2 窄间隙通过（检验贡献 C3：胶囊 + 角圆障碍物模型）

**场景**：双车道窄路，一辆静止公交车停靠在右侧路缘（距路缘 0.3 m），
自车只能从左侧剩余间隙 g 通过。

- 道路半宽 H = (g + 2.30 + 0.30) / 2；障碍物中心 n_o = −H + 0.30 + 1.15。
- 横向目标为间隙中线 n_t = 1.30 m（裁剪到 |n| ≤ H − 1.35）。
- 网格（非随机，全组合）：
  - g ∈ {2.8, 3.0, 3.3, 3.6, 4.0, 4.5, 5.0, 5.5, 6.0} m
  - κ ∈ {0, 1/60, 1/35, −1/40} m⁻¹
  - 初速度 ∈ {8, 11} m/s
  - 障碍物起点 s = 30 m，速度 0
- 共 72 个场景。

**方法（9 个）**：

- 本文：`paper6_hybrid_sqp`
- 本文几何消融：`paper6_capsule_sqp`、`paper6_circles_sqp`、`paper6_circles5_sqp`
- Reiter：`reiter_{direct,lifted}_{ellipse,circles}`
- Xing：`xing_joint_corridor`

**运行前的解析预测**（直道、车身对齐，几何最小可通过间隙 g_min）：

| 几何 | 横向所需中心距 | g_min |
| --- | ---: | ---: |
| 精确矩形 / 胶囊 Eq. (23) / Xing 矩形（直道） | 2.50 m | 2.70 m |
| **本文 hybrid（胶囊 + 4 角圆，25 对全约束）** | **2.98 m** | **3.18 m** |
| 三圆 / 五圆（半径 W/√2 = 1.626 m） | 3.45 m | 3.65 m |
| Reiter 椭圆 | 5.27 m | 5.47 m |

数值由各方法自身的约束函数计算（扫描纵向错位 ±12 m 取最坏值），脚本见
`scripts/measure_minimum_gap.py`。

> **更正（全量运行前，单场景冒烟测试后）**：初版预测把本文 hybrid 当作精确矩形（2.70 m）。
> 实际上角圆半径 √2·W/4 = 0.81 m、圆心横向偏移 W/4，横向外凸到 1.39 m > 1.15 m，
> 因此 hybrid 在车端横向保守约 0.24 m。冒烟测试中 g = 2.8 m 直道 hybrid 首帧无解，
> 与此一致。本更正只改预测，不改场景、方法与指标。

预测：

- g < 3.18 m 时，本文 hybrid 不能通过，**直道上 Xing 矩形与胶囊可以通过，本文在此区间预期落后**；
- 3.18 ≤ g < 3.65 m 时，本文能通过而圆类不能；
- g < 5.47 m 时椭圆不能通过。

弯道上 Xing 冻结足迹在 Frenet 下的外包会变大，表现以实测为准。

**主指标**：通过率（按 g 分组）。次要指标：最小障碍物净空、最小道路净空、约束违反。

## 2. E1 窄弯路贴边行驶（检验贡献 C1：变形车身轮廓的道路约束）

**场景**：窄弯路贴外侧路缘行驶（进站、紧贴路缘转弯）。横向目标设在外侧，
等于参考点模型允许的边界 n_t = −sign(κ)(H − 1.35)，规划器会把车推向外侧约束。
障碍物置于路外 30 m（n = −sign(κ)·30，s = 30 m，静止），不参与交互。

- 网格：
  - H ∈ {2.5, 3.5} m
  - κ ∈ {±1/15, ±1/20, ±1/30, ±1/40} m⁻¹
  - 初速度 ∈ {5, 8} m/s
  - 满足 v²|κ| ≤ 4.5 m/s²
- 共 32 个场景。

**方法（6 个）**：

- 本文：`paper6_hybrid_sqp`；C1 消融：`paper6_frozen_sqp`（冻结航向偏差）
- Reiter：`reiter_direct_ellipse`（借用本文轮廓约束）、`reiter_direct_ellipse_point`（原文参考点约束）
- Xing：`xing_joint_corridor`（借用本文轮廓约束）、`xing_joint_corridor_point`（原文 Eq. 12 参考点约束）

**主指标**：精确评估下的最小道路净空：

- 越界率：最小道路净空 < 0
- 裕量违反率：最小道路净空 < 0.19 m
- 贴边程度：|最小道路净空 − 0.2|，越小说明越不保守

**预测**：参考点约束在弯道上不计前悬外摆，预期越界；轮廓类约束预期净空接近 0.2 m。

## 2b. 公平性复核（看到公交车结果之后追加，明确标为事后）

公交车结果中，Xing 重构的失败多为 SQP 在 50 次迭代内未达到可行性容差 1e-4。
本文与 Reiter 的 acados SQP 上限为 150 次。两者的接受判据相同
（求解成功且违反量 ≤ 1e-4），但迭代上限不同。

因此追加一组 Xing 迭代上限 150 的运行：

- 覆盖两种车辆、两个任务；
- 主表仍按冻结协议（50 次）报告，150 次作为敏感性结果并列；
- 若结论因此改变，以对 Xing 更有利的一组为准写入回复。

## 4. 事后追加：设置对齐（2026-10-30 晚，明确标为事后）

前三节的协议与结果**保持不变**，作为冻结协议的正式结果。以下追加内容在看到
冻结结果之后才确定，**属于事后分析**，在回复信中与主表并列给出。

### 4.1 触发原因

逐例比对「本文 hybrid 失败、对比方法成功」的所有格点后，发现本文输给对比方法的
例子里有三种并非方法能力差异，而是实验设置差异：

1. **节点 0 约束漏设（本文复现代码的缺陷）**
   acados 在节点 0 不应用 `con_h_expr`，而复现代码没有设置 `con_h_expr_0`，
   于是求解器**不约束实际执行的那一步控制 u₀**（横向 jerk、转向速率），
   但验收检查按全约束判定，等于给本文 SQP 设了 Reiter 没有的门槛。
   表现为超越任务 case 15/19/20/30/35 首帧违反量 0.153~0.197 而失败。
   修复：节点 0 只约束依赖 u₀ 的两行（若把只依赖状态的行也放进节点 0，
   首帧 QP 会因 x0 不可行而报 status 4）。

2. **首帧初值不对称**
   冻结协议下本文的冷启动初值沿中线外推，**直接穿过障碍物**，非凸碰撞约束
   从该点出发不收敛；Reiter 的默认初值不穿过障碍物；Xing 的凸走廊对初值不敏感。
   表现为窄间隙任务本文丢掉 8 例（公交 4 + SUV 4）。

3. **验收规则过严**
   迭代用满（status 2）但解可行且违反量 ≤ 1e-4 的迭代点被判为失败，
   例如一般任务 case 33。

### 4.2 对齐后的设置（对所有方法统一生效）

| 项 | 冻结协议 | 对齐设置 | 作用范围 |
| --- | --- | --- | --- |
| 节点 0 非线性约束 | 无 | 仅 u₀ 相关的 2 行 | **仅本文 SQP**（缺陷修复） |
| 首帧初值 | 各方法自带冷启动 | 恒速 + 横向渐变到目标 | 所有方法 |
| 验收 | 仅 status 0 | 另接受 status 2（违反量 ≤ 1e-4） | 所有方法 |
| 轮廓分段 N_disc | 5 | 5（另测 10） | 本文 |

三项改动分别记录在每份 `protocol.json`（`initial_guess`、`accept_maxiter`、
`stage0_nonlinear_constraints`、`n_disc`）。

### 4.3 公平性声明

- 改动 1 是本文复现代码的缺陷修复，**方向对本文有利**，因此在回复中同时给出
  修复前后的数字，并说明缺陷机制。
- 改动 2、3 对所有方法统一生效，双方都受益：公交窄间隙任务中 Reiter 椭圆
  2/72 → 10/72，本文 42/72（只修 bug）→ 52/72。**本文绝对增量更大**，
  因此对齐结果只作敏感性结果，主表仍用冻结协议。
- 两处对 Reiter 有利的不对称，如实披露：
  1. Reiter 使用原作者代码，求解失败时会自动重置并重试一次；本文复现代码没有。
  2. Reiter 的默认初值不穿过障碍物；本文冻结协议的冷启动会穿过。
- Xing 的 SQP 迭代上限（§2b）由 50 提高到 150 后结果不变，已并列给出。

### 4.4 三套结果的关系

- **冻结协议**：正式协议，主表引用。
- **只修 bug**：仅修复节点 0 约束，检验缺陷修复本身的影响。
- **对齐设置**：三项改动全部生效，作为敏感性结果并列给出。

三套结果全部归档于仓库 `results/archived/narrow/`。

## 5. 第二版实验（2026-10-31 冻结，运行前写定）

本节在看到 §4 结果后制定，目的是把实验对准论文主张，并修掉 §1–§4 中发现的设计缺陷。
旧结果全部保留归档，不删除、不覆盖。所有运行统一使用 §4 的对齐设置
（`BENCH_INITIAL_GUESS=ramp BENCH_ACCEPT_MAXITER=1`）。

### 5.1 Xing 复现的实现细节

诊断发现 Xing 的失败多为实现细节，而非方法本身：
OSQP 返回 `solved inaccurate` 即中止 SQP；keep-left 墙的开关在每轮 SQP 迭代重新判定，导致迭代振荡。
新增两个开关（论文未规定，属实现细节）：

| 开关 | 含义 |
| --- | --- |
| `BENCH_XING_ACCEPT_INACCURATE=1` | 接受 OSQP `solved inaccurate` 的迭代点，最终仍由非线性残差 ≤ 1e-4 把关 |
| `BENCH_XING_FREEZE_CORRIDOR=1` | keep-left 墙每帧按热启动轨迹判定一次，帧内 SQP 迭代不再切换 |

**规则（事先约定）**：四种组合在第一版任务上各跑一遍，按"六个任务的总通过数"选出 Xing 的最优变体，
第二版所有任务对 Xing 一律使用该变体。选择只看 Xing 自己的结果。

### 5.2 窄间隙 v2（`--task gap2`）

间隙按 0.1 m 步长覆盖各几何的临界区：公交 2.7–4.2 m 加 4.5/5.0/5.5/6.0 m（160 例），
SUV 2.3–3.6 m 加 4.0/4.4/4.8 m（136 例）。曲率、速度、障碍物位置同第一版。
判据同第一版：完成、超过障碍物、障碍物净空 ≥ 0.19 m。另统计碰撞次数。

**预测**（公交 / SUV，最窄可过间隙）：
- 本文 hybrid：3.2–3.3 m / 2.7–2.8 m（理论下限 3.18 / 2.69 m）；
- 圆覆盖（本文与 Reiter）：3.7–3.8 m / 3.1–3.2 m；
- Reiter 椭圆：≥ 5.5 m / ≥ 4.4 m；
- Xing 矩形走廊：直道可能低于 hybrid（矩形本身更精确），弯道因 Frenet 包络膨胀而变宽；
- 若 Xing 在直道上的最窄间隙小于本文，如实报告，不作解释性剔除。

### 5.3 贴边 v2（`--task curb`，加两条基线）

沿用第一版贴边任务（目标贴在参考点模型允许的外侧边界，对应公交贴路沿停靠），
轮廓分段统一为 N_disc = 10，并加入：
1. `reiter_direct_ellipse_inflated`：参考点边界 + 按曲率的静态外侧膨胀
   （车身与后轴圆弧相切时外前角的外摆量）——参考点模型的常见工程修补；
2. Xing 矩形走廊的最优变体（§5.1）。

指标：碰路沿次数、完成数、最小净空、平均外侧净空（越接近 0.2 m 表示越能贴边）。

**预测**：
- 已发表的参考点边界与冻结航向：全部碰路沿（同第一版）；
- 静态膨胀：不碰路沿；本路段为等曲率圆弧，车身姿态与膨胀假设一致，预计与本文**持平**；
- Xing 矩形走廊（最优变体）：不碰路沿，能完成多数案例；
- 本文的贴边优势因此只能表述为"无需手工膨胀即达到同等安全"，
  若要显示变形轮廓相对静态膨胀的优势，需要曲率变化路段（缓和曲线、进出弯），
  本版不做，作为局限写明。

### 5.4 窄路超车 v2（`--task overtake2`）

双车道窄路（公交半宽 3.5–4.5 m），前方慢车在右车道。生成器只保留运动学上
在 120 步内可以完成超越的案例（以最大加速度、限速估计），并检查起始位姿的车身净空。
判据统一为：完成、超过障碍物、障碍物净空 ≥ 0.19 m。

### 5.5 重跑

消融、六/九状态串行计时、维度扩展（去掉冷启动全部失败的 N = 80 档）用节点 0 修复后的代码重跑。

### 5.6 Xing 变体的选择结果（按 §5.1 规则）

Xing 走廊在第一版六个任务上的总通过数：原版 108，仅接受 inaccurate 114，仅冻结走廊 166，
**两者都开 175**。第二版对 Xing 统一使用两者都开（`BENCH_XING_ACCEPT_INACCURATE=1
BENCH_XING_FREEZE_CORRIDOR=1`）。该变体使 Xing 在贴边任务从 0/32 升至 30/32（公交）、
2/32 升至 24/32（SUV），一般任务的 yield 策略升至 40/40。第一版中"Xing 走廊在贴边任务求解中止"
的结论因此撤回：那是复现实现的缺陷，不是方法本身。结果归档于 `results/xingvar/`。
